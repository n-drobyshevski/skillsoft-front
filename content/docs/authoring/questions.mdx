# Написание вопросов

Вопросы оценки - это инструменты измерения поведенческих индикаторов. Качество вопросов напрямую влияет на точность и надежность всей системы оценки.

## Три типа вопросов

SkillSoft использует три типа вопросов с рекомендуемым распределением:

| Тип | Доля | Назначение |
|-----|------|------------|
| **Шкала Лайкерта** | 70% | Самооценка согласия с утверждением |
| **Ситуационные суждения (SJT)** | 25% | Оценка поведения в конкретной ситуации |
| **Множественный выбор (MCQ)** | 5% | Проверка знания принципов |

<Callout type="info">
Такое распределение основано на психометрических исследованиях: Лайкерт надежен и быстр, SJT дает контекст и предсказывает поведение, MCQ проверяет базовые знания.
</Callout>

## Шкала Лайкерта (70%)

### Структура

Утверждение + шкала согласия от 1 до 5:

1. Совершенно не согласен
2. Не согласен
3. Нейтрально
4. Согласен
5. Полностью согласен

### Пример качественного вопроса

```
Утверждение: "Я изменяю способ объяснения информации
в зависимости от уровня знаний собеседника"

Индикатор: Адаптирует стиль общения под аудиторию
Сложность: FOUNDATIONAL (базовый)
Время: 30 секунд
```

### Правила написания

**Делайте:**

| Правило | Пример |
|---------|--------|
| Используйте простой язык | "Я слушаю собеседника до конца" |
| Одна идея на утверждение | "Я запрашиваю обратную связь" |
| Настоящее время | "Я делаю..." а не "Я бы делал..." |
| Конкретные формулировки | "...перед принятием решения" |

**Не делайте:**

| Ошибка | Плохой пример | Хороший пример |
|--------|---------------|----------------|
| Двойные отрицания | "Я не могу не согласиться" | "Я согласен" |
| Несколько идей | "Я слушаю и даю обратную связь" | Два отдельных вопроса |
| Крайности | "Я всегда..." | "Я обычно..." |
| Длинные утверждения | 30+ слов | До 20 слов |

### Обратные вопросы

Для предотвращения "автопилотных" ответов можно использовать обратные формулировки:

```
Прямой: "Я адаптирую стиль общения под собеседника"
Обратный: "Мне сложно менять манеру общения с разными людьми"
```

<Callout type="warning">
В текущей версии SkillSoft обратное кодирование не применяется автоматически. При использовании обратных вопросов учитывайте это при интерпретации.
</Callout>

### Чеклист Лайкерта

- [ ] Утверждение ясное и однозначное
- [ ] Одна идея на вопрос
- [ ] Нет двойных отрицаний
- [ ] Настоящее время
- [ ] Длина до 20 слов
- [ ] Нет крайних формулировок (всегда/никогда)
- [ ] Соответствует индикатору

## Ситуационные суждения - SJT (25%)

### Структура

Описание ситуации + 3-5 вариантов ответа с разными баллами:

```
Ситуация: Описание рабочего сценария (2-4 предложения)

Варианты ответа:
A) Оптимальное действие (5 баллов)
B) Хорошее действие (4 балла)
C) Приемлемое действие (3 балла)
D) Неоптимальное действие (1 балл)
```

### Пример качественного SJT

```
Ситуация:
Вам нужно объяснить сложную техническую концепцию команде,
в которую входят опытные разработчики и новые сотрудники
из отдела маркетинга. Дедлайн проекта приближается.

Что будет лучшим подходом?

A) Провести две отдельные встречи с контентом,
   адаптированным под уровень каждой группы
   → 5 баллов (оптимально: максимизирует понимание обеих групп)

B) Начать с базовых концепций, постепенно добавляя
   техническую глубину
   → 4 балла (хорошо: использует scaffolding подход)

C) Создать дополнительную документацию для тех,
   кто менее знаком с технической терминологией
   → 3 балла (приемлемо: поддержка есть, но первичная
   коммуникация не адаптирована)

D) Презентовать на техническом уровне, необходимом
   разработчикам, маркетинг разберется позже
   → 1 балл (неоптимально: игнорирует разнообразие
   аудитории)

Индикатор: Адаптирует стиль общения под аудиторию
Сложность: INTERMEDIATE
Время: 180 секунд (3 минуты)
```

### Правила создания сценариев

**Качественный сценарий должен быть:**

| Критерий | Описание |
|----------|----------|
| **Реалистичным** | Основан на реальных рабочих ситуациях |
| **Релевантным** | Соответствует целевой должности/роли |
| **Конкретным** | Содержит достаточно контекста |
| **Сложным** | Требует размышления, нет очевидного ответа |

### Правила создания вариантов ответа

**Качественные варианты:**

- **Правдоподобны** - все варианты реалистичны
- **Дифференцированы** - четкие различия в качестве
- **Исчерпывающи** - покрывают спектр подходов
- **Сбалансированы** - нет абсурдных вариантов

**Распределение баллов:**

| Качество | Баллы | Описание |
|----------|-------|----------|
| Оптимальное | 5 | Лучший возможный подход |
| Хорошее | 4 | Эффективный подход с небольшими минусами |
| Приемлемое | 3 | Работает, но не оптимально |
| Недостаточное | 2 | Частично решает проблему |
| Неоптимальное | 1 | Неэффективный или вредный подход |

### Чеклист SJT

- [ ] Сценарий реалистичный и конкретный
- [ ] Контекста достаточно для принятия решения
- [ ] 3-5 вариантов ответа
- [ ] Все варианты правдоподобны
- [ ] Баллы корректно отражают качество вариантов
- [ ] Есть объяснения для каждого варианта
- [ ] Нет очевидно абсурдных вариантов
- [ ] Время достаточно для чтения и размышления (2-3 минуты)

## Множественный выбор - MCQ (5%)

### Структура

Вопрос + 4 варианта ответа (один правильный):

```
Вопрос: Какой фактор НАИБОЛЕЕ важен при адаптации
стиля коммуникации под аудиторию?

A) Личные предпочтения говорящего
B) Существующий уровень знаний аудитории ✓ (правильный)
C) Время суток, когда происходит общение
D) Физический размер группы слушателей

Индикатор: Адаптирует стиль общения под аудиторию
Сложность: FOUNDATIONAL
Время: 60 секунд
```

### Правила написания

**Делайте:**

- Тестируйте принципы и основы
- Используйте формулировки "НАИБОЛЕЕ важен" или "ЛУЧШИЙ подход"
- Делайте дистракторы правдоподобными, но явно неверными
- Выравнивайте длину вариантов ответа

**Не делайте:**

- Тестирование тривиальных фактов
- "Все вышеперечисленное" или "Ничего из вышеперечисленного"
- Делать правильный ответ очевидно отличающимся
- Давать подсказки в формулировке вопроса

### Качество дистракторов

Дистракторы (неправильные варианты) должны быть:

| Характеристика | Описание |
|----------------|----------|
| **Правдоподобны** | Могут показаться верными неподготовленному |
| **Связаны с темой** | Относятся к области вопроса |
| **Разнообразны** | Представляют разные типы ошибок |
| **Недвусмысленны** | Явно неверны при внимательном анализе |

### Чеклист MCQ

- [ ] Вопрос тестирует принцип, а не тривиальный факт
- [ ] 4 варианта ответа
- [ ] Только один правильный ответ
- [ ] Дистракторы правдоподобны
- [ ] Варианты похожи по длине и структуре
- [ ] Нет подсказок в вопросе
- [ ] Нет "все/ничего из вышеперечисленного"

## Уровни сложности

Каждый вопрос должен иметь уровень сложности:

### FOUNDATIONAL (Базовый)

**Характеристика:** Базовые принципы и осведомленность.

**Типичное содержание:**
- Простые утверждения для самооценки
- Базовые принципы и понятия
- Ясные, недвусмысленные ситуации

**Целевая аудитория:** Новички, начало карьеры

---

### INTERMEDIATE (Средний)

**Характеристика:** Применение в стандартных ситуациях.

**Типичное содержание:**
- Реалистичные рабочие сценарии
- Необходимость применить знания
- Умеренная неопределенность

**Целевая аудитория:** Середина карьеры

---

### ADVANCED (Продвинутый)

**Характеристика:** Сложные ситуации с неопределенностью.

**Типичное содержание:**
- Многофакторные сценарии
- Конфликтующие интересы
- Необходимость стратегического мышления

**Целевая аудитория:** Старшие специалисты

---

### EXPERT (Экспертный)

**Характеристика:** Стратегический уровень, системное мышление.

**Типичное содержание:**
- Организационное влияние
- Лидерские вызовы
- Инновационные решения

**Целевая аудитория:** Руководители, эксперты

## Психометрические аспекты

### Индекс дискриминации

**Что это:** Способность вопроса различать людей с разным уровнем компетенции.

**Целевые значения:**

| Значение | Интерпретация |
|----------|---------------|
| > 0.40 | Отличный вопрос |
| 0.30 - 0.40 | Хороший вопрос |
| 0.20 - 0.30 | Приемлемый, требует мониторинга |
| < 0.20 | Слабый, рассмотреть доработку |

**Как улучшить:**
- Уточнить формулировку
- Убедиться в соответствии индикатору
- Проверить варианты ответов на очевидность
- Упростить излишне сложные формулировки

### Индекс сложности

**Что это:** Процент людей, "правильно" отвечающих на вопрос.

**Оптимальный диапазон:** 0.30 - 0.70

| Значение | Проблема | Решение |
|----------|----------|---------|
| > 0.80 | Слишком легкий | Усложнить или удалить |
| < 0.20 | Слишком сложный | Упростить или пересмотреть |

<Callout type="tip">
Система автоматически отслеживает эти показатели после накопления 50+ ответов. Подробнее в разделе [Психометрика для HR](/docs/psychometrics).
</Callout>

## Временные лимиты

| Тип вопроса | Лимит | Обоснование |
|-------------|-------|-------------|
| Шкала Лайкерта | 30 секунд | Простое согласие |
| Множественный выбор | 60 секунд | Чтение + оценка 4 вариантов |
| Ситуационные суждения | 180 секунд | Чтение сценария + анализ вариантов |

<Callout type="note">
При истечении времени ответ засчитывается как 0. Это мотивирует отвечать, но не спешить чрезмерно.
</Callout>

## Избежание предубеждений

### Культурные предубеждения

**Проблема:** Вопрос содержит культурно-специфичные отсылки.

**Плохо:** "Во время обеденного перерыва в корпоративной столовой..."
**Хорошо:** "Во время рабочего совещания..."

### Гендерные предубеждения

**Проблема:** Вопрос содержит гендерные стереотипы.

**Плохо:** "Ваш руководитель, он..."
**Хорошо:** "Ваш руководитель..."

### Профессиональные предубеждения

**Проблема:** Вопрос предполагает определенную профессию.

**Плохо:** "На совете директоров..."
**Хорошо:** "На важном совещании..."

## Полный чеклист качества

Перед публикацией вопроса убедитесь:

### Содержание

- [ ] Связан с конкретным поведенческим индикатором
- [ ] Уровень сложности соответствует целевой аудитории
- [ ] Формулировка ясная и однозначная
- [ ] Нет культурных или гендерных предубеждений

### Структура

- [ ] Формат соответствует типу вопроса
- [ ] Варианты ответов корректно оформлены (для SJT/MCQ)
- [ ] Правила оценивания четко определены
- [ ] Временной лимит адекватен

### Качество

- [ ] Эксперт проверил содержание (оценка 4.0+)
- [ ] Пилотное тестирование пройдено (если новый)
- [ ] Индекс дискриминации >= 0.30 (или ожидается)
- [ ] Метаданные заполнены (теги, сложность)

## Рабочий процесс создания вопроса

<Steps>

### Определите индикатор

Выберите поведенческий индикатор, который будет измерять вопрос.

### Выберите тип вопроса

На основе характера индикатора выберите подходящий формат.

### Напишите черновик

Следуйте рекомендациям для выбранного типа вопроса.

### Проведите самопроверку

Используйте соответствующий чеклист.

### Получите ревью

Покажите вопрос коллеге или эксперту.

### Внесите правки

Учтите замечания и доработайте.

### Пилотное тестирование

Для новых вопросов рекомендуется пилот на 50+ человек.

### Мониторинг

После публикации отслеживайте психометрические показатели.

</Steps>

## Частые ошибки и их исправление

### Ошибка: Вопрос не различает уровни

**Симптом:** Все отвечают одинаково (индекс сложности > 0.9 или < 0.1)

**Причина:** Вопрос слишком очевидный или слишком абстрактный

**Решение:** Добавить конкретный контекст или сложность

---

### Ошибка: Отрицательная дискриминация

**Симптом:** Менее компетентные отвечают "лучше"

**Причина:** Вопрос измеряет что-то другое, двусмысленность

**Решение:** Переформулировать или удалить вопрос

---

### Ошибка: Низкая дискриминация

**Симптом:** Индекс дискриминации < 0.20

**Причина:** Вопрос не связан с компетенцией или слишком неопределенный

**Решение:** Уточнить связь с индикатором, упростить формулировку
