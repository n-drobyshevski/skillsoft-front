# Система сборки тестов

Узнайте, как SkillSoft автоматически формирует тесты под разные задачи оценки и что контролирует HR-администратор в этом процессе.

## Зачем нужна автоматическая сборка?

Когда вы создаете тест, система автоматически подбирает вопросы на основе:

- Выбранных вами компетенций
- Типа теста (цели оценки)
- Качества доступных вопросов

Это обеспечивает:
- **Валидность** - тест измеряет то, что должен измерять
- **Надежность** - результаты воспроизводимы
- **Эффективность** - оптимальное количество вопросов

<Callout type="info">
Вы контролируете **что** оценивать (компетенции и тип теста), а система определяет **как** это измерить (какие вопросы использовать).
</Callout>

## Три типа тестов

SkillSoft поддерживает три сценария оценки, каждый со своим алгоритмом сборки.

### Паспорт компетенций (Overview)

**Цель:** Создание универсального профиля навыков сотрудника.

**Когда использовать:**
- Оценка всех сотрудников организации
- Формирование базового профиля новичка
- Планирование развития
- Кадровый резерв

**Особенности:**

| Характеристика | Значение |
|----------------|----------|
| Фокус | Широкий охват компетенций |
| Сравнение | Без эталона, нейтральная оценка |
| Результат | Профиль сильных сторон и зон развития |
| Вердикт | Нет (только профиль) |

**Как работает сборка:**

Система равномерно распределяет вопросы по всем выбранным компетенциям, чтобы получить сбалансированную картину:

<Diagram>
```
Компетенция 1          Компетенция 2          Компетенция 3
     |                      |                      |
+----+----+            +----+----+            +----+----+
|    |    |            |    |    |            |    |    |
И1   И2   И3           И1   И2   И3           И1   И2   И3
|    |    |            |    |    |            |    |    |
Q1   Q2   Q3           Q4   Q5   Q6           Q7   Q8   Q9
```
</Diagram>

<Callout type="tip">
Паспорт компетенций - это отправная точка. Результаты можно использовать для последующих целевых оценок (Job Fit, Team Fit).
</Callout>

---

### Соответствие должности (Job Fit)

**Цель:** Оценка соответствия кандидата требованиям конкретной должности.

**Когда использовать:**
- Подбор персонала
- Внутреннее продвижение
- Ротация кадров
- Аттестация на должность

**Особенности:**

| Характеристика | Значение |
|----------------|----------|
| Фокус | Компетенции, важные для должности |
| Сравнение | С эталоном O*NET |
| Результат | Степень соответствия + gap-анализ |
| Вердикт | Соответствует / Не соответствует |

**Как работает сборка:**

Система использует международную базу O*NET для определения требований должности и фокусируется на ключевых компетенциях:

1. Загружается профиль должности из O*NET (по коду SOC)
2. Определяются приоритетные компетенции
3. Больше вопросов назначается критичным компетенциям
4. Учитывается уровень строгости оценки

<Callout type="note">
**O*NET** - это американская база данных профессий, содержащая требования к компетенциям для тысяч должностей. SkillSoft использует эти данные как научно обоснованный эталон.
</Callout>

**Настройка строгости:**

Параметр "Уровень строгости" (0-100) влияет на порог прохождения:

| Строгость | Порог прохождения | Применение |
|-----------|------------------|------------|
| 0 (мягкая) | 50% | Начальные позиции, обучаемые роли |
| 50 (средняя) | 65% | Стандартные позиции |
| 100 (жесткая) | 80% | Критичные роли, senior-позиции |

---

### Командная совместимость (Team Fit)

**Цель:** Оценка способности кандидата усилить существующую команду.

**Когда использовать:**
- Формирование проектных команд
- Подбор в существующий коллектив
- Реструктуризация отделов
- Замена ключевого сотрудника

**Особенности:**

| Характеристика | Значение |
|----------------|----------|
| Фокус | Компетенции, недостающие команде |
| Сравнение | С профилем команды |
| Результат | Вклад в команду + совместимость |
| Вердикт | Усиливает команду / Не усиливает |

**Как работает сборка:**

Система анализирует текущий состав команды и определяет "пробелы" - компетенции, которых команде не хватает:

<Diagram>
```
Профиль команды (текущий):
+-------------------------------------------------+
| Коммуникация   ████████████████████ 80% (ОК)    |
| Лидерство      ██████               30% (!)     |
| Критич.мышл.   ███                  15% (!!)    |
| Командная раб. ████████████         60% (ОК)    |
+-------------------------------------------------+

Приоритет вопросов:
1. Критическое мышление (15% - критический пробел)
2. Лидерство (30% - умеренный пробел)
3. Остальные компетенции
```
</Diagram>

**Логика оценки:**

- Кандидат ценен, если закрывает пробелы команды
- Избыток в уже сильных областях менее полезен
- Учитывается баланс разнообразия и насыщения

<Callout type="warning">
Для Team Fit необходимо, чтобы члены команды уже имели результаты оценки (хотя бы Паспорт компетенций).
</Callout>

## Процесс сборки теста

### Что происходит при создании теста

<Steps>

### Вы выбираете параметры

- Тип теста (Overview / Job Fit / Team Fit)
- Компетенции для оценки
- Дополнительные настройки (строгость, команда и т.д.)

### Система выбирает стратегию

В зависимости от типа теста активируется соответствующий алгоритм сборки.

### Отбираются качественные вопросы

Система проверяет психометрическое качество каждого вопроса и исключает проблемные.

### Формируется порядок вопросов

Вопросы распределяются для оптимального покрытия всех индикаторов.

### Тест готов к прохождению

Создается сессия тестирования для сотрудника.

</Steps>

### Визуализация процесса

<Diagram>
```
Шаблон теста                    Сессия тестирования
(что оценивать)                 (конкретное прохождение)
      |                                |
      v                                v
+-------------+                 +--------------+
| Компетенции |                 | Сотрудник    |
| Тип теста   | ----сборка----> | Вопросы      |
| Настройки   |                 | Ответы       |
+-------------+                 | Результаты   |
                                +--------------+
```
</Diagram>

## Что контролирует HR vs Система

| Аспект | HR-администратор | Система |
|--------|------------------|---------|
| Выбор компетенций | Да | - |
| Выбор типа теста | Да | - |
| Настройка строгости | Да | - |
| Выбор конкретных вопросов | - | Да |
| Порядок вопросов | - | Да |
| Фильтрация некачественных вопросов | - | Да |
| Расчет результатов | - | Да |

<Callout type="tip">
Вы определяете стратегию оценки, а система обеспечивает ее качественную реализацию.
</Callout>

## Фильтрация вопросов

Перед включением в тест каждый вопрос проверяется:

### Автоматическая фильтрация

| Критерий | Действие |
|----------|----------|
| Статус RETIRED | Исключается |
| Отрицательная дискриминация | Исключается |
| Менее 50 ответов | Допускается с ограничениями |
| ACTIVE статус | Приоритет |

### Приоритет вопросов

1. **Первый приоритет:** Проверенные вопросы (ACTIVE, 50+ ответов)
2. **Второй приоритет:** Вопросы на испытательном сроке (PROBATION, менее 50 ответов)
3. **Исключаются:** Отключенные вопросы (RETIRED)

<Callout type="note">
Подробнее о статусах вопросов читайте в разделе [Психометрика для HR](/docs/psychometrics).
</Callout>

## Рекомендации по выбору типа теста

### Используйте Паспорт компетенций когда:

- Нужна общая картина навыков сотрудника
- Планируете развитие персонала
- Формируете кадровый резерв
- Проводите массовую оценку

### Используйте Job Fit когда:

- Подбираете кандидата на конкретную позицию
- Оцениваете готовность к продвижению
- Проводите аттестацию
- Есть четкие требования к должности

### Используйте Team Fit когда:

- Формируете новую команду
- Ищете замену в существующую команду
- Хотите усилить слабые стороны коллектива
- Важна командная динамика

## Версионирование шаблонов

Каждый шаблон теста проходит жизненный цикл из трёх статусов:

| Статус | Описание | Можно редактировать? |
|--------|----------|----------------------|
| **Черновик (DRAFT)** | Шаблон в работе. Все поля доступны для изменений | Да |
| **Опубликован (PUBLISHED)** | Шаблон готов к использованию и доступен сотрудникам | Нет |
| **В архиве (ARCHIVED)** | Шаблон выведен из обращения | Нет |

<Diagram>
```
DRAFT ──(публикация)──> PUBLISHED ──(архивирование)──> ARCHIVED
                              |
                              └── (новая версия) ──> DRAFT (копия)
```
</Diagram>

### Правило неизменяемости

<Callout type="warning">
Опубликованный шаблон **нельзя редактировать**. Это гарантирует, что все сессии, созданные по одному шаблону, проходят одинаковый тест. Результаты остаются сравнимыми.
</Callout>

Если вам нужно изменить опубликованный шаблон:

1. Создайте **новую версию** (система скопирует все настройки)
2. Внесите изменения в черновике
3. Опубликуйте новую версию
4. При необходимости архивируйте старую

## Анонимное тестирование

SkillSoft позволяет проводить тестирование без авторизации — через **ссылку-приглашение**. Это удобно для оценки внешних кандидатов, которые не имеют учётной записи в системе.

### Как это работает

<Steps>

### HR генерирует ссылку

Из опубликованного шаблона создаётся уникальная ссылка вида `/take/[token]`.

### Кандидат открывает ссылку

Ссылка работает без входа в систему. Кандидат видит описание теста.

### Кандидат заполняет данные

Перед началом теста запрашиваются:
- **Имя** и **фамилия** (обязательно)
- **Email** (необязательно)
- **Примечания** (необязательно)
- **Согласие на обработку данных** (GDPR)

### Прохождение теста

Кандидат отвечает на вопросы в обычном режиме. Навигация (пропуск, возврат) определяется настройками шаблона.

### Просмотр результатов

После завершения кандидат получает страницу результатов по ссылке `/results/[token]` с HMAC-подписью для безопасного доступа.

</Steps>

### Технические детали

| Параметр | Значение |
|----------|----------|
| Время жизни сессии | 24 часа |
| Хранение сессии | localStorage браузера |
| Авторизация | Токен сессии (X-Session-Token) |
| Доступ к результатам | HMAC-подписанная ссылка (бессрочная) |

<Callout type="info">
Результаты анонимного тестирования доступны HR-пользователям так же, как и результаты авторизованных сотрудников — включая разбивку по компетенциям и общий балл.
</Callout>

<Callout type="note">
Анонимные сессии привязаны к конкретному браузеру. Если кандидат откроет ссылку в другом браузере или очистит данные, потребуется начать заново.
</Callout>

## Часто задаваемые вопросы

**Сколько вопросов будет в тесте?**

Зависит от количества выбранных компетенций и доступных вопросов. Обычно 3-5 вопросов на индикатор, 3-8 индикаторов на компетенцию.

**Можно ли добавить свои вопросы в тест?**

Да, через создание вопросов в разделе [Написание вопросов](/docs/authoring/questions). После создания вопросы автоматически включаются в пул для сборки.

**Почему мой вопрос не попал в тест?**

Возможные причины:
- Вопрос имеет статус RETIRED
- Вопрос относится к индикатору, не включенному в выбранные компетенции
- Система выбрала другие вопросы того же индикатора
